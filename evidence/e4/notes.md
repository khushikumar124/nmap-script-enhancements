# E4 notes (Nmap 7.99)
Measured first: with servers on 465 (smtp), 993 (imap), 995 (pop3), 636 (ldap), 990 (ftp) and 563 (nntp), all wrapped in TLS, stock unusual-port flagged all six (measure.txt), although Nmap itself reported `ssl/smtp`, `ssl/imap` etc. The script compares the plain name (smtp) with the nmap-services name (smtps, imaps, pop3s, ldapssl, ftps, snews) and never looks at `service_tunnel`.
Enhanced version accepts a service with `service_tunnel == "ssl"` when the table name is the service plus "s", or when the port is in the small `tlschecks` table (465, 563, 636). On Nmap 7.99 port 465 is `smtps`, so it follows the "+s" rule and the 465 entry is only a safeguard for nmap-services versions that list it under another name (the plan said 465 does not follow the naming). ssh inside TLS on 993 and plaintext smtp on 993 are still flagged (negative.txt). No new connections (requests.txt). No structured-output change in E4, so there is no xml.txt.
